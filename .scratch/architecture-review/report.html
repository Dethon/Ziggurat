Candidates

1 · Give the tab protocol a module

Strong in-process

Infrastructure/Clients/Browser/PlaywrightWebBrowser.cs · 1780
Infrastructure/Clients/Browser/BrowserSessionManager.cs · 712
Tests/Unit/Infrastructure/BrowserSessionManagerTests.cs · 682  |  Tests/Integration/Clients/BrowseTabsTests.cs · 231

Before — 33 call sites, ordering by hand
After — one intent, one arrow
Problem

BrowserSessionManager is deep inside and shallow at its edge: 47 public members, 33 call sites, and a nine-step ordering every operation re-derives by hand. The ordering is the interface, and it exists only in prose.

Solution

Move the seam from "nine verbs the caller sequences" to "one entry point that takes what the operation is and the work to do." The manager owns acquisition, locking, the closed re-check, touch, navigation detection, the stamp lease and the wall disambiguation — once each.

Wins
  • Locality: one ordering, one file
  • Three IsClosed spellings become one
  • Interface becomes the test surface
  • ~11 sequencing fixes become unit tests
Evidence
  • 34 test reaches past the seam, 8 files
  • Sessions: "Nothing in production reads this"
  • 36 policy facts, zero caught these bugs
ADR-0034 asks for this. It already states the pool policy lives in BrowserSessionManager and "PlaywrightWebBrowser only carries pages around." Today that sentence is aspirational; this makes it true. No decided behaviour changes.

2 · One label ladder, two renderers

Strong ports & adapters

Infrastructure/HtmlProcessing/PageImageEntry.cs · 145  (FirstSpoken 97–102, Sanitize 128–132)
Infrastructure/Clients/Browser/PlaywrightWebBrowser.cs · 961–987 (the same ladder, in JavaScript)

Before — one rule, two languages
After — one definition, two renderings
Problem

The label ladder is implemented twice — six rungs, the same bracket rounding, the same 500-character cut — in C# and in a JavaScript string literal 800 lines away. Nothing but a comment holds them together, and it has failed twice. Delete the JS copy and complexity does not vanish; it reappears in the C# ladder that already exists. That is a pass-through duplicate.

Solution

State the ladder once and emit the page-side script from it. The mechanism is already proven: the JS block interpolates {{PageImageEntry.WidthAttribute}} from C# today — the attribute names were taken along, the ladder was not. Separately, pull the whole byte-acquisition sequence to C# and let the page answer only facts.

Wins
  • Two-sided edit hazard stops existing
  • ~130-line JS block becomes a probe
  • Rung ladder unit-testable both sides
  • Acquisition order assertable with fakes
Evidence
  • ~7 of 30 web fixes are this drift
  • Coverage depends on JPL being up
  • Rules file spends a paragraph policing it
No ADR conflict. ADR-0033 decides the rung order and the credentials rule — both survive verbatim. This changes only how many times each is written. The "don't use credentials: 'include'" warning stays load-bearing.

3 · Move the guard onto the scenario

Strong in-process

Tests/Eval/ClaimExemptions.cs · 208 (159-line dictionary literal)
Tests/Eval/ClaimCoverageTests.cs · 92  |  Tests/Eval/ScorecardLedger.cs · 122  |  Tests/Eval/Scenarios/*.cs

Before — a table a file away from both ends
After — the compiler holds the link
Problem

A guard is a property of the relationship between a scenario and a claim, stored a file away from both and linked only by 16 "see ClaimExemptions" comments. The taxonomy has been outlived by its own success: every non-Guard kind was closed by backlog commits, leaving one kind — and one kind is not a taxonomy.

Solution

Give Scenario a second list beside Claims: the claim it guards and the note on why it cannot cite. The claim id is already a compile-time symbol, so a renamed or withdrawn claim breaks the file that guards it.

Wins
  • Locality: guard prose beside its scenario
  • One concept, one type, not two
  • A contradiction test gets deleted
  • Five dead enum values stop being decoration
Evidence
  • 29/29 entries verified as one kind
  • Hottest non-browser file: 25 touches
  • Scenario edits force a second-file edit
Touches ADR-0031, does not contradict it. A guard is not an uncovered claim — a scenario runs and asserts it — so this is a distinction 0031 did not draw rather than one it settled. Every claim still needs a scenario or a written reason, and the backlog stays visible in the scorecard. Worth a short amending ADR, since 0031's "either a scenario or a line in the exemption list" reads literally as today's shape.

4 · Make the conversation identity a type

Strong live defect

Problem

One identity is spelled as a string at 8 sites and mapped back at 4 more, across a process boundary and ~40 hops. The round trip is only correct because a dictionary stays alive across it. When it doesn't, ?? conversationId hands a raw chatId:threadId to a lookup that cannot match — the chunk is dropped and a reply silently disappears.

Solution

Let the identity cross signatures as a type that carries both spellings, authored once. The composition and its inverse become its implementation; the fallback that drops chunks becomes unrepresentable rather than untested.

Wins
  • Closes a live silent-drop defect
  • 8 composition sites become one
  • 4 inverse mappings become one
  • Locality: the round trip reads as one thing
Also in this sweep
  • ReplyContentType.ToolCall: no producer, 4 unreachable case arms, 9 tests that exist only to enter them
  • RegisterAgentsTool ×5, identical but for prose (87 lines)
  • MCP host boilerplate: leave alone — 5.4% ceremony, any abstraction would be shallow
No ADR conflict. ADR-0018 is working as designed — one route, correctly — which is exactly why ToolCall is now residue from the route 0018 deleted. Removing it completes that decision rather than reopening it.

5 · Give the body window an owner

Worth exploring

Infrastructure/HtmlProcessing/HtmlProcessor.cs · 179–229  |  HtmlConverter.cs · 54–107  |  PageImageEntry.cs · 62–89
Infrastructure/Agents/Mcp/McpImageLift.cs · 159  |  Domain/Agents/ReadImageHydration.cs · 101

Before — positions ride on an out int
After — one module whose interface is a window
Problem

Paging coordinates are spread over three modules with no owner. Separately, the picture-index rule is written twice — McpImageLift and ReadImageHydration each split paragraphs independently, across an assembly split, held together by a comment reading "It has to be the same question, asked the same way." They have already disagreed once, putting every image one key off its bytes.

Solution

One module owning the window and its four facts, with truncation and the entry detectors as private detail. For the index rule: put the paragraph split in Domain — it is pure text with no infrastructure in it — and have the bridge call it, the way ImageRef is already shared for exactly this reason. Note the dependency direction forces this way round.

No ADR conflict. ADR-0033's four decisions — nextOffset measured not inferred, an entry never split, a window always advances, the index counts {-paragraphs — all survive verbatim. Only which module states them changes, and the measurement must stay at the cut.

Checked and working — leave alone

ScenarioChecks

368 lines behind a two-argument function; ten checks composed in a ten-line table. The deepest module in the suite. Do not split.

ModalDismisser

638 lines, one entry point, a real result type. Took four fixes — every one a policy fix inside it, none a sequencing fix at its caller. What the rest should look like.

IWebBrowser

6 methods, 4 adapters. A real seam, and the tools test cleanly through it. No change proposed.

The eval harness's own tests

Drive real recordings through the same entry point the runner calls. No test reaches around the seam — exactly what ADR-0030 asks for.

Scenario is wide (22 members, 18 reachable types, 81 hand-written permissions) — but hold off

A named tolerance profile would cut ~36 declaration lines per scenario. Real friction, and one drift already exists: MountScenarios and VoiceScenarios allow delegation without setting WorkerAnswer, silently taking a default that is a success string — the thing WebScenarios documents as harmful. Worth doing after candidate 3, which touches the same type. Any profile must stay an exhaustive named set — never a wildcard — or ADR-0030's permitted-set guarantee is lost.

Top recommendation

Start with the tab protocol

It is the largest module, the hottest by churn, and the one whose bugs the existing tests structurally cannot catch. Thirty-six policy facts pass while eleven sequencing bugs ship, because the tests are the caller — they perform the ordering rather than checking it. That is the signature of a seam in the wrong place, and Sessions being commented "Nothing in production reads this" is the codebase saying so out loud.

It also has the least argument against it: ADR-0034 already asserts this shape. The work makes a decided sentence true rather than reopening anything.

Then candidate 2 — it shares files, and the interpolation mechanism it needs is already working in that same JS block. Candidate 4 can go independently and in parallel; it closes a live defect where a reply silently vanishes, and it is the smallest of the five.
