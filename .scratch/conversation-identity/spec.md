# Spec — The conversation identity is a type

Status: ready-for-agent

Origin: `.scratch/architecture-review/report.md`, Candidate 4 ("Make the conversation identity a type"), grilled to a settled design on 2026-08-30. The grilling corrected the report on its central claim, and the correction binds: the "live silent-drop defect" is the designed offline path — ADR-0035 now records that contract — and the real defect on that path is elsewhere, an approval request that deadlocks the agent's run forever. The glossary already pins **Conversation identity**; both documents are in the working tree beside this spec.

## Problem Statement

One identity is spelled by hand at roughly a dozen production sites and unspelled at six more, across two channel servers and a process boundary. The chat hub composes the chat-and-thread spelling six times; two Telegram tools carry byte-identical parsers of it, each privately knowing that an equal thread and chat means a non-forum chat; four sites map the composed spelling back to the topic a client opens, three of them coercing a miss into a value that can never match anything, so that intent — degrade to persisted-only delivery, by design — reads as an accident and logs a warning per chunk, hundreds per offline turn. A domain record carrying both spellings already exists and dies at its factory: every caller immediately projects it down to a string, after which a topic-shaped parameter accepts a conversation-shaped value without complaint at some forty-five signatures, and one upload signature takes both spellings positionally adjacent at the same type. On the same miss path, an approval request registers itself under the coerced value, drops its prompt unseen, and awaits an answer with no timeout that not even deleting the topic can release — a scheduled agent reaching an approval-gated tool with nobody connected hangs its run forever. Around the edges sit residue the review swept up with the candidate: a reply content kind with zero producers kept alive by an unreachable-code suppressor attribute, a voice preamble whose only trigger is that dead kind while a hand-rolled unguarded copy of it runs live in the approval tool, three byte-identical agent-registration tools, and a second colon composite — chat and topic — that shares the spelling while meaning something else.

## Solution

The existing domain record becomes the authored home of the identity: a value type on the established key pattern, composing its conversation spelling once, parsing it back once — returning nothing rather than guessing when handed some other channel's address — and owning the non-forum rule the Telegram parsers duplicate. It travels through the SignalR and Telegram channel servers, so composition sites become constructor calls, parse sites become the one inverse, and the coercing fallbacks become unrepresentable: a miss is an explicit null handled the way the conversation-create tool already handles it, logged at debug because ADR-0035 says the path is designed. The deadlocked approval request fails fast with a denial the persisted reply makes visible. The dead reply kind and its formatter are deleted, completing ADR-0018; the voice preamble is re-wired onto the live approval surface with its once-per-turn guard and its own playback kind; the three identical registration tools collapse into one shared tool; the lookalike composite gets a name of its own so it can never again be mistaken for a conversation identity.

## User Stories

1. As a maintainer, I want the conversation identity's two spellings authored in one type, so that a composition or its inverse is never written by hand at a call site again.
2. As a maintainer, I want the type to be the existing domain record reshaped rather than a second overlapping type, so that Domain holds one answer to what a conversation identity is.
3. As a maintainer, I want the conversation spelling derived from the identity rather than stored beside it, so that the record cannot carry two fields that disagree.
4. As a maintainer, I want parsing to return nothing for a value that is not a conversation identity, so that a satellite id, a correlation id, or an eval id is rejected as not-mine instead of half-parsed or thrown on.
5. As a maintainer, I want the non-forum rule — an equal thread and chat means no thread — owned by the type, so that the two Telegram tools stop privately agreeing on it.
6. As a maintainer, I want the chat hub's composition sites to construct the identity instead of interpolating strings, so that the round trip reads as one identity instead of one that changes name mid-flight.
7. As a maintainer, I want the session service's maps and lookups keyed by the identity's spellings through the type, so that a topic-shaped lookup cannot be handed a conversation-shaped value.
8. As a maintainer, I want the upload-minting signature to take the identity instead of two adjacent same-typed strings, so that swapping the arguments is a compile error instead of an invisible bug.
9. As a maintainer, I want the three coercing fallbacks replaced by the explicit null-check shape the conversation-create tool already has, so that the designed miss reads as designed.
10. As an operator reading logs, I want an offline turn's undeliverable chunks logged at debug rather than a warning per chunk, so that a routine scheduled delivery does not spam the log with false alarms.
11. As a schedule owner, I want an approval-gated tool call with no live session denied immediately with the reason named, so that my scheduled run completes and the denial is readable in the persisted reply instead of the run hanging forever.
12. As a schedule owner, I want auto-approval notifications on the same path to stay fire-and-forget, so that an invisible notification costs nothing and blocks nothing.
13. As a WebChat user, I want live streaming, resume, cancel, delete, uploads and approvals to behave exactly as before when my topic is open, so that the identity work is invisible to a connected client.
14. As a maintainer, I want the unreachable reply kind, its formatter, and all four channel arms deleted, so that the route ADR-0018 removed stops leaving residue that suggests a second one exists.
15. As a voice user, I want the agent's spoken acknowledgement before slow tool work delivered once per turn, so that the first tool call flushes it and mid-run narration stays buffered for the answer.
16. As a voice user, I want that preamble spoken under its own playback kind, so that the queue treats an acknowledgement as an acknowledgement and not as an approval prompt.
17. As a maintainer, I want the preamble logic to live in the reply speaker behind one public entry point, so that the approval tool calls it instead of keeping a hand-rolled unguarded copy.
18. As a maintainer, I want the three byte-identical agent-registration tools replaced by one shared tool, so that the next channel server registers it instead of copying it.
19. As a maintainer, I want the two outlier registration tools left alone, so that the hub-broadcasting one and the no-op one keep the shapes their servers need.
20. As a maintainer, I want the chat-and-topic index composite built by a named helper, so that the next reader cannot mistake it for a conversation identity that merely shares the colon.
21. As a channel-server author, I want the sanctioned hot-path exception to the protocol's one-spelling rule written into the channel rules, so that the hand-built reply dictionary reads as deliberate and stays byte-identical to the reflective path.
22. As a reviewer, I want each sub-change landed as its own red-green step, so that any regression bisects to one commit.
23. As a future reader, I want ADR-0035 and the glossary's conversation-identity entry to carry the offline contract and the term, so that the next architecture review does not mistake the designed path for a defect again.

## Implementation Decisions

All settled in the grilling; none are open.

- **Reach is the channel servers, not the pipe.** The identity type travels through the SignalR and Telegram servers — the hub's six composition sites, the session maps, the four inverse sites, the two parsers, the upload signature. The agent core keeps the string: past the channel servers the id is genuinely polymorphic (satellite id, correlation id, eval id), and a single struct is the wrong shape there. The delivery-target resolver's four mutually-assignable nullable strings are acknowledged and explicitly not touched.
- **The type is the existing record reshaped, on the agent-key pattern.** Readonly record struct per house style; the conversation spelling derived, not stored; a total render and a partial inverse that returns null for non-conforming input; the non-forum rule inside it. The narrowing to the Telegram API's int thread id stays in the Telegram projection — the type speaks longs.
- **The miss is explicit, quiet, and per ADR-0035.** The three coercing fallbacks take the null-check-and-return shape; severity drops to debug because the path is designed. No channel-side buffering, no failing loudly — both were considered and rejected in the ADR.
- **The approval deadlock fails fast.** A request-mode approval that finds no live session returns a denial naming the reason instead of registering and awaiting; notify mode stays fire-and-forget. This is the one behavioral fix a user can observe, and it rides the same identity-miss detection as the streaming path.
- **The dead reply kind goes entirely.** The enum member, the formatter file, all four channel case arms, and the nine test references. Verified safe: the wire carries the member name as a string so nothing renumbers; the only producer explicitly skips function calls in favor of the approval flow; every producer and consumer ships from one compose build; the outpost has no reply surface; nothing persists the kind. A consuming arm without a producer is dead code — no compatibility window is owed.
- **The voice preamble re-wires onto the live surface.** The reply speaker gains one public preamble entry taking the session and the conversation id; the approval tool's notify branch calls it instead of its hand-rolled flush. The entry claims the turn's preamble exactly once, speaks under the preamble playback kind at normal priority, and never touches the turn handshake — the microphone-and-turn separation of ADR-0013 and the queue contract of ADR-0003 both hold. The observable change is deliberate: today's notify branch speaks on every call; after this, the first tool call of a turn wins and mid-run narration stays buffered.
- **The registration dedup is one shared tool plus two survivors.** A shared catalog-writing tool in the hosting assembly, constructor-injecting the mutable catalog, one generic description — the no-outbound-surface precedent, registered explicitly per the never-assembly-scanning rule. Telegram, voice and scheduling adopt it; the SignalR one keeps its hub broadcast and the library one keeps its no-op. Telegram's explanatory comment about why it holds a catalog at all moves to its registration site.
- **The lookalike gets a name.** The chat-and-topic index member used by the thread-state store and the topic search documents is built by one named helper whose comment states it is not a conversation identity.
- **The channel rules gain the sanctioned exception.** The hot-path hand-built reply dictionary is documented as the one deliberate divergence from the protocol's one-spelling claim, with the byte-identical-wire obligation stated.
- **Documentation is already done.** ADR-0035 and the glossary entry are in the working tree; the implementing change lands beside them and adds no new ADR.
- **Order: small green steps, TDD each.** (1) The reshaped type with its compose/parse/rule tests, red-first. (2) SignalR adoption — hub, session service, stream and approval services, upload signature — with the explicit-miss shape and debug severity. (3) The approval fail-fast, red-first via a request that today never completes. (4) Telegram adoption, deleting the twin parsers. (5) The reply-kind deletion and the preamble re-wire, migrating the seven tests. (6) The registration dedup, the lookalike helper, the rules edit.

## Testing Decisions

- A good test asserts observable behavior at an existing seam — what a hub method returns, what a tool answers, what the queue receives, what the log records — never the private shape of a map or the wording of an interpolation. Everything here is deterministic unit-test territory; no armed run, no container.
- **Zero new seams.** The type is tested directly beside the generator and key tests, the house precedent for value objects: render, inverse, null on non-conforming input, the non-forum rule, round-trip. The SignalR services are tested through the existing stream-, approval- and session-service tests: the miss path's early return and severity, and the fail-fast denial — red-first as a request that never completes today. The hub tests continue to pass untouched, which is itself the assertion that a connected client sees no change. The Telegram tool tests assert parsing through the type and a loud error on a non-conforming id where an unguarded parse used to throw. The reply-speaker tests migrate their seven preamble assertions to the public entry point; the voice approval-tool tests gain the once-per-turn and playback-kind assertions. The registration tools keep their per-server tests, and the one server table's contract tests police that the shared registration does not disturb any server's shape.
- Prior art: the agent-key tests for the value object; the existing approval- and stream-service tests for the miss path; the redial test that uses the dead kind only incidentally is re-expressed without it rather than deleted.

## Out of Scope

- **The agent core's identity.** Every string signature past the channel servers — the channel message, the conversation context, the delivery target, the agent key — stays a string. Making the delivery-target resolver's shared-anchor threading typed is a candidate for a later pass, not this one.
- **A discriminated identity across channels.** Satellite ids, correlation ids and eval ids remain plain strings on their channels; the type rejects them by returning null and nothing more.
- **Persisting approvals for later render.** The fail-fast denial is the whole fix; an approval inbox for offline users is a separate feature.
- **The voice preamble's content or prompting.** What the agent is prompted to say before slow work is untouched; only the delivery mechanics move.
- **The other review candidates** — the tab protocol, the label ladder, the scenario guards, the body window — share no files and stay independent.
- **Redis key layouts.** The lookalike helper names an existing spelling; no key changes shape, nothing migrates.

## Further Notes

- The report's Candidate 4 section must not be taken over this spec where they disagree: its "live defect" framing of the chunk drop and its "fail loudly" one-liner were both falsified by reading the delivery contract — ADR-0035 is the record. The report also undercounted: the hub has six composition sites, not four.
- A later exploration claimed the Telegram arm keeps the dead reply kind alive; it does not — the kind has zero producers, so every consuming arm is equally unreachable. Deletion is full.
- The eval fixture's `eval:`-prefixed ids and the stub session service's bare GUIDs are deliberate non-conforming spellings; they are exactly what the null-returning inverse exists for, and make good test inputs.
- The preamble change is the one place this spec intentionally alters live behavior beyond logging: once per turn instead of once per notify call. The reply-speaker tests already document that intent; the approval tool merely never honored it.
