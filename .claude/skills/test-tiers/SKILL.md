# Test tiers that cost money or need a stack

A bare `dotnet test` runs none of these for pay (only the two canaries). Each one below is armed by an environment variable and runs only when the user asked for it.

## Smoke tier

The **smoke tier** (`[Trait("Category", "Smoke")]`, `Tests/Smoke/`) asks a running stack what the conformance tests read in the files: who gets past Caddy, what the sandbox reaches, what is published, that a forged call or identity from inside the network is refused by every server and app, that the home's servers are reached through their tunnels alone and a forged tunnel credential is refused, a browse page answering through the tunnel, two signed-in replies from the real agent, one reading the vault through its tunnel, and a household onboarded end to end (created on the dashboard's operator route, its owner keyed and its agent named through the admin API, a reply from that agent on the household's own key — the deployment's, on this machine alone — then suspended and its next turn refused; another that mints its own vault's credential has its agent read a note through that vault's tunnel, never the home's — `scripts/smoke-stack.sh household-vault` starts it; another saves its Lemonade box as reached through the tenant kit, mints `lemonade` and starts the kit's forwarder in front of a stand-in box — `scripts/smoke-stack.sh household-lemonade` — and finds the box's model in its own picker and not in the home's; another adds the voice template's agent under a name of its own and mints its voice credential, and a second kit voice server with a test satellite of its own hears that agent answer and a one-minute timer ring there, while one with voice and no voice agent hears the refusal aloud instead of silence — `scripts/smoke-stack.sh household-voice` starts them, beside the home's `voice`, which stays as it was) — on a stack the household migration made, so the home's agents are offered by their seeded names, a reply's topic and model usage are the home's, and a schedule from before households is moved into it. It needs the stack `scripts/smoke-stack.sh up` starts on this machine (the shipped compose file and Caddyfile from empty state, the household migration run as the deploy runs it, Caddy on its local CA, a household-configuration master key made for its state and a stub (`smoke-keys`) answering every key probe — working, or refused for a key with "refused" in it and unreachable for one with "unreachable", nothing that reaches the deployment's bots, satellites or home; beside it the tenant kit as project `tenant-kit-smoke`, its credentials minted from the stack's own accounts service and its tunnels opened to this machine's Caddy — web search (the Brave key in `McpServerWebSearch`'s user secrets saved into the home's keys section and its CapSolver key handed to the kit, where there are any, so a hand-driven turn can search), vault, library, sandbox and printer (to a stand-in that prints nothing), and a bare machine running the outpost binary published from the checkout (`smoke-machine`, whose file the home's Jonas reads through its tunnel), never Home Assistant, and voice only for `scripts/smoke-stack.sh voice`, which starts it with a test satellite (`TenantKit/smoke/`) and Lemonade on the CPU and checks a spoken answer and a timer ringing on the satellite — `TenantKit/docker-compose.override.smoke.yml`), then `scripts/smoke-stack.sh test`, and `down` to remove both; it skips unless `ZIGGURAT_SMOKE=1`. It always connects to 127.0.0.1 by the deployment's hostnames — never point it, or the stack, at the deployment's host. Its replies cost a few cheap model calls.

## Behavioural eval

The behavioural eval (`[Trait("Category", "Eval")]`, `Tests/Eval/`) is the one category a bare `dotnet test` does **not** run, even with an OpenRouter key present. It drives a real model against the shipped agent definition — plus a pinned judge model (`Tests/Eval/Harness/Judge.cs`) for the scenarios that carry rubric checks — so a routine test run must never spend money without being asked: `ZIGGURAT_EVAL=1 dotnet test --filter "Category=Eval&Tier=Full"` for one complete pass (`Tier=Smoke` for one canary per family; `ZIGGURAT_EVAL_CHANGED=<ref> ... --filter "Category=Eval&Tier=Changed"` for only the scenarios whose claims a diff against the ref's merge base touched, `1` meaning `master`; a bare `Category=Eval` runs every tier and pays for the canaries twice). The changed tier sees prompt sections, skills and scenario files — a tool description or a fixture edit selects nothing, so run the family or the full tier for those (`docs/adr/0041`). Failures land in the gitignored `.eval-output/`, beside a scorecard with per-claim and per-scenario rates, the pass's rate again per agent (`summary.byAgent` — a model is picked per agent, and nabu's voice scenarios ask for different things than jonas's written ones), a `coverage` field per claim, and a `spend` per scenario and per pass (cost, tokens, and the share of input the provider served from cache — read off the same usage events the deployment's metrics read, the judge's verdicts and Jev's judgments included — with a `byModel` split under it, so the agent, the rubric judge and Jev each show as a model like any other; read the agent's cache share there, since the total's counts the judges' uncached input too). Its harness — the checks, the run policy, the dump, the claim coverage, the judge's material and verdict parsing — is deterministic and runs on a bare invocation like anything else; armed runs also start the real sandbox image as a testcontainer. A scenario stops once k of its runs have passed — set `ZIGGURAT_EVAL_EXHAUSTIVE=1` to take every declared run, which is what a model-bump diff wants so both scorecards rate over the same N (`docs/adr/0040`). A scenario's runs go out together up to its policy's width, and `ZIGGURAT_EVAL_PARALLELISM` (default: half the cores, between 4 and 12) bounds how many stacks stand at once across the whole process — raise it on a big machine, lower it if the provider rate-limits. `ZIGGURAT_EVAL_MODEL=<openrouter id>` drives the pass on another model without editing `Agent/appsettings.json` (every agent, and so every subagent — a worker runs its parent's model — with the shipped `only`/`order` pin lifted and the rest of the routing kept); `ZIGGURAT_EVAL_PROVIDER=<slug>` pins it to one provider. The eval **preloads** as the deployment does: Jev is reached through OpenRouter on the same `openRouter:apiKey` the pass already needs, so it is asked which skills each turn needs and a confident answer puts the body into the conversation before the model's first call, so a trigger claim is met by either loader and the scorecard's `loader` split (host / model / nobody, per claim, per scenario and per pass) says which — read it before blaming a description. A pass with `skillPreload:enabled` false runs with the preload off and the scorecard says `"preload": "off"`. Jev's tokens and cost sit inside `spend` under its model id in `byModel`, the cost being what OpenRouter's usage said each judgment charged; a preloaded skill outside a scenario's permitted set reddens it like any wrong load, and the dump names it as the host's. See `docs/adr/0030`, `docs/adr/0031`, `docs/adr/0032`, `docs/adr/0040` and `docs/adr/0041`.

## Research tier

The **research tier** (`Tier=Research`, `Tests/Eval/Scenarios/ResearchScenarios.cs`) is the one family the full tier leaves out: it scores a model instead of guarding a prompt, cites no claim, and is run per model by name — `ZIGGURAT_EVAL=1 ZIGGURAT_EVAL_MODEL=<openrouter id> dotnet test --filter "Category=Eval&Tier=Research"`. Its rungs come in two groups, each with a score of its own (`summary.grades.byGroup`): **base**, on sites of a dozen pages a model can read whole — reading with traps, plus the four medical turns — and **scale**, on a generated site of about eighty-five pages that cannot be (`ArchiveCorpus.cs` — fifty-five monthly bulletins with no totals, half a year of them counted in boxes and one republished corrected, a notice among fifteen that changed a figure, a search that caps its results and returns a bulletin only to a query naming its year), where the question is which pages to read and what cannot be added as it stands. A rung's call ceiling is **reported, not enforced** (`Scenario.CeilingReported`): what an answer cost in calls is on the scorecard beside its marks (`calls` per scenario, `summary.calls`), because the first comparison's best model was right nearly everywhere by reading everything and a red for thoroughness said the opposite of its score. Most of its rungs research one sealed corpus (`Tests/Eval/Fixtures/SolarCorpus.cs` — a stale page that ranks first, a forum, a newspaper that contradicts the minutes, a fees page no search returns, a monthly table, a question nothing answers); two more are medical, each on a corpus of its own and each asked by a user who has said no doctor is reachable — a twisted ankle (`SprainCorpus.cs`) and, where a wrong answer hurts either way, a type 1 sick day with ketones (`SickDayCorpus.cs`: the extra insulin dose is a share of the person's own daily total off a table no search returns, and the first results say to halve or skip the insulin) — and add an `actionability` mark, which rewards a plan with doses and self-checkable warning signs and marks down a generic "see your doctor" — a concrete warning sign or threshold with what to do about it is advice, not a deferral, and sending somebody the plan keeps at home to a hospital is one; the rubrics say both; `ZIGGURAT_EVAL=1 dotnet test --filter "Category=EvalCalibration"` puts three hand-written replies per medical rung (a plan, half a plan under a referral, a referral) to the judge and asserts their order, and is rerun after any edit to those rubrics. Every run is **graded**, green or not: `Scenario.Graded` declares dimensions marked 0–10 — `accuracy` counted from planted facts wherever a list can say what is true, `grounding` counted too (the pages a right answer rests on that the reply names and somebody opened — judged, it came back nine or ten for every reply), and `reasoning` put to the judge with the ground truth written into the rubric, since the judge never sees a page. A rung still passes or fails on its small contract (it searched, finished, carries its headline figure); the marks land on the scorecard as `grades` per scenario and `summary.grades` (`score`, `byDimension`), and each pass is filed as `scorecard-research-<model>.json`, so two models are two files. All but five rungs take the agent's workers away (`WorkerMode.None`) to measure what the model finds alone; five run **real workers** (`WorkerMode.Real`) on the parent's model, and the recording keeps a worker's calls apart from its parent's. Every other scenario keeps canned workers.

## Sugary tier

The **Sugary tier** (`Tier=Sugary`, `Tests/Eval/Sugary/`) scores the shipped `sugary` agent on the standalone Sugary app's 64 benchmark meals and its 14 Nutrition5k dishes again as video (`video-cases.json`, a clip naming its stills), per model by name like the research tier, and skips unless a model is named: `ZIGGURAT_EVAL=1 ZIGGURAT_EVAL_MODEL=<openrouter id> dotnet test --filter "Category=Eval&Tier=Sugary"`. Each meal is one turn sent as the Sugary channel sends an estimate (`MealTurn.Text`, the `meal_estimate` format, the photo as an attachment whose fetch the stack answers — `EvalAttachments`, since an eval dials no channel), and the last message is read by the server's own `MealEstimateReply`; the `benchmark` section of `scorecard-sugary-<model>.json` gives mean absolute error, bias, truth inside the range, estimated against true weight, median seconds and cost per estimate, overall, per set, per input (photo or video) and per set and input, then every meal. One photo per meal unless `ZIGGURAT_EVAL_SUGARY_PHOTOS=<n>`. The photos and clips are not in git (`Tests/Eval/Sugary/README.md` says where they come from; `fetch-clips.sh` makes the clips; a missing file skips the tier). The same pass reruns the sugary agent's scenarios (`SugaryScenarios.cs`, which the full tier also runs) on that model. A stack starts only the servers its agent dials (`EvalStack.Dialled`), so a sugary run stands up Sugary's server and no sandbox.
