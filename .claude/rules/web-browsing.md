# Web Browsing Architecture

McpServerWebSearch exposes the `web_*` browse tools. The `websearch_prompt` (`Domain/Prompts/WebBrowsingPrompt.cs`) is the standing stub — the browser exists, a url comes from a search, no call is a probe — and the workflow, principles, error recovery and answer style are the `web-browsing` skill (`Domain/Prompts/WebBrowsingSkill.cs`, shipped through `AddSkills`; `docs/adr/0039`). The tools run over `PlaywrightWebBrowser`, a WebSocket to Camoufox. The accessibility snapshot assigns interactive element refs (`e-1`, `e-2`, …) that `web_action` then addresses, pages are kept alive per session with cookie persistence, and cookie banners, newsletters and age gates are auto-dismissed.

**A page whose own script moved it onto an error is asked for once more.** A bot check answers
200, sends the page on, and has the server refuse that follow-up while leaving behind what lets the
next visit through — Reddit's "You've been blocked by network security" on a fresh session's first
browse. `BrowsePageAsync` reads the settled document's status (`performance`'s navigation entry,
since the commit's response belongs to the page that left) and browses the caller's address once
more; a second landing reports the error. `HttpStatus` is that settled status, not the commit's.
A navigation the page's script has started but the server has not yet answered is waited for
(`MainFrameNavigationWatch`, up to 10s) before the page is read — read early, the browse extracted
the check itself — and a stability reading torn down by a navigation counts as a change, not an error.

## Browsing as a person

Logins are handed off, never typed by the model: the person logs in on a live view of a tab in their own browser context and the agent inherits the session. `.scratch/web-identity/spec.md` is the design; what follows is what the code cannot say for itself.

**A person is resolved, never claimed.** `IdentityMap` (`Domain/Tools/Web`) maps each person's Telegram username, WebChat name and enrolled voice to one name; the map is per-deployment compose environment (`IDENTITY__PEOPLE__<n>__*`), never `appsettings.json`, and a slot with no name is no person, so the shipped placeholders are the feature off. `asMe` on `web_browse` and `web_login` resolve the call's `ConversationContext.UserId` through it; an unmapped user, the voice `household` fallback (refused even if somebody maps it) or an empty map is a refusal by name. Nothing falls back to the anonymous context or to another person.

**A user id is only as true as the channel that sent it.** Each id is matched on its own channel alone — the Telegram username on `telegram`, the WebChat name on `signalr`, the enrolled voice on `voice`, by the turn's `Origin.ChannelId` — and only on a channel `Identity:VerifiedChannels` lists (this server's `appsettings.json`, shipped `["telegram", "voice"]`, empty in code because the binder appends to a defaulted list). A turn from any other channel is nobody, refused saying where to ask instead. WebChat is off the list because its user is whatever `ChatHub.RegisterUser` was handed by an unauthenticated picker: listed, anyone who opens WebChat could pick a name and act on that person's sessions. **Switching WebChat on is the multi-user work's**: verify who the WebChat user is (a real login behind the hub), then add `signalr` to the list — and that also lights up a voice login's WebChat delivery, refused until then. Telegram is matched by **username**, which its owner can change and Telegram can reassign; numeric user ids belong to that same work. **A fire's identity is weaker still**: its `Origin.ChannelId` is its first delivery target (`DeliveryTargetResolver.BuildConversationContext` — `signalr` by default from `Domain/delivery.json`, so a default schedule resolves to nobody) and its `UserId` is the `userId` its author wrote into the schedule or watch, a model-written field no channel vouched for; a `deliverTo: ["telegram"]` schedule naming a person's Telegram username resolves as them.

**The person is asked before the agent acts as them on a site.** `asMe` is a flag the model sets per call, so a page's injected text can ask for it. Agent-side, `ToolApprovalChatClient` puts any call carrying `asMe: true` to the person, whatever the whitelist or a remembered tool says, with the `as_person` reason code (`ExecScreenCodes.AsPerson`); approve-and-remember covers that tool on that site (`AsPersonSubject`: the tool plus `RegistrableDomain.Of` the url's host) for the rest of the conversation and never the tool itself, kept apart from the tool-level set the exec bridge reads. A call with no parseable url is asked every time. A schedule's, watch's or download's fire is not asked — its approvals go to the channel it delivers to, where nobody is waiting — and runs as the whitelist says; what bounds where a fire may act as the person is this server's rule, not the gate. A login wake is asked like the person's own turn. Refs still carry no flag, so `web_action` on an `asMe` tab is not asked again.

**Contexts, not fingerprints, separate people.** The browser holds the anonymous context (every browse without `asMe`, carrying nobody's cookies) and one person context per person, made on their first use over a connection (`PlaywrightWebBrowser.ContextForAsync`) and restored from their remembered state. A tab belongs to its context for life (`BrowserTab.Context`); reuse-before-open and the composed snapshot's address match only within it, and a popup joins its opener's. Refs need no flag — a ref still finds its own tab — so `web_action`, `view_image`, `web_snapshot` and `back` act as the person exactly when the ref's tab is theirs, which is how a worker on its parent's session reaches the parent's `asMe` tabs. The envelope names `asMe`. A reconnect closes every context; person contexts come back lazily, restored.

**The handoff tab is outside every pool.** `web_login` opens its url through `IHandoffBrowser` (`PlaywrightHandoffTabs`): a page in the person's context that no browse session admits, so no ref, browse or action can reach it while the person types. It is refused on any turn with an `OriginKind` (schedule, watch, download, the login handoff's own turns) and withheld from workers agent-side (`AgentSpec.WithheldTools`, with `web_logins`), because a worker's calls carry its parent's context. Who may be handed a link is the Domain tools' (`WebLoginTool`, `WebLoginsTool`, over `ILoginHandoffs`/`ILoginsPages`); the tab, the link and the view are the server's (`LoginHandoffs`, `LoginsPages`), and the browser's and the store's interfaces (`IHandoffBrowser`, `IPersonContexts`, `IPersonStateStore`) live in Infrastructure, since no Domain code consumes them. The link (`OneTimeLinks`, Redis, single use) is `Handoff:PublicBaseUrl` + `/browse/handoff/<token>` — Caddy routes `/browse/*` on the assistants host here. **The link's GET only shows the page**; previewers and prefetch issue GETs, so the page's own `POST …/claim` spends the token atomically and binds an HttpOnly, SameSite=Strict cookie (`Secure` behind Caddy's `X-Forwarded-Proto`), which every later request answers to. A claim for a tab this process no longer holds refuses, because a ticket outlives a restart and its tab does not. A Done whose tab the browser lost answers 410 and wakes nobody. The handoff tab's dialogs are dismissed — the person never sees one through the screencast — and its visited hosts are every main-frame navigation request, redirect hops included, since a single sign-on's intermediate pages set cookies of their own. `LoginHandoffs` keeps the live handoffs in memory with one `TimeProvider` timer: ten minutes to claim, thirty for the view, either running out closes the tab and emits nothing. **A handoff's hold on the person's logins is one object**: `PersonLogins.BeginHandoffAsync` hands out a `HandoffLease` before the tab opens, the `LiveHandoff` carries it, and every way out — a mint or open that fails, Done, Done on a lost tab, expiry — settles it with `CompleteAsync` or `AbandonAsync`. The first settle wins and later ones are no-ops, an unsettled lease abandons on dispose, and "a handoff is open" means the person holds an unsettled lease; there is no counter to pair by hand, which is what two earlier bugs came from.

**The live view is a screencast.** Frames are `page.Screencast` JPEGs (Camoufox's juggler serves them, ~20 fps at 1280x720) sent as binary WebSocket messages, newest only — a frame arriving while one is being sent is dropped. Input comes back as JSON at fractions of the frame and is dispatched through the page's mouse and keyboard; DOM `key` names go to `Keyboard.Down/Up`, a phone keyboard's composed text to `InsertText` through the visible text box (a phone shows no keyboard without a focused input). The page on top — the tab or its newest open popup — is the one shown and typed into. The page is a served string (`HandoffPage`), WebChat's palette, no typed glyphs.

**Done wakes the conversation that asked.** The browse server is a channel server too (`BufferAlways`, subscriber `channel-websearch`, no outbound surface), dialled as the `websearch` channel endpoint. Done emits one `LoginWake`: the asking context's conversation, agent and user, `ReplyTo` its origin target (a satellite's address included), origin `Login`. Grouping is by conversation and agent, so it queues behind a running turn of a live group, and a group that is not live delivers to the reply target.

**A voice login's link goes to WebChat; its answer comes back on the satellite.** nabu cannot speak a link, so `web_login` on a turn whose origin is the `voice` channel also emits a fire into a new WebChat conversation (`LoginWake.LinkInWebChat`: reply target `signalr` with no conversation, so SignalR mints one; sender and user the person's WebChat name from the identity map; origin `Login`) asking the agent to present the link, and WebChat's end-of-stream Web Push pings the space. The tool's answer carries no link, only that it is in WebChat. Anyone who picks the person's WebChat name would see that conversation, so the delivery runs only while `signalr` is a verified channel; until then, and for a person with no WebChat name, a voice login is refused before anything opens and nabu tells them to ask from Telegram. The wake's reply target is the voice turn's own, satellite address included, so a live satellite session speaks the answer and none binds it as an announcement on that satellite alone.

**Remembered state is sealed, and a save is an allowlist.** `RedisPersonStateStore` keeps one AES-GCM record per person (version byte, nonce, tag, ciphertext; the person's name is the associated data) under `Logins:StateKey` from secrets (`LOGINS__STATEKEY`, base64 of 32 bytes; empty is remembering off, malformed fails startup). A record it cannot open — no key, or the wrong one — throws `PersonStateUnreadableException`, and every `asMe` and `web_login` for that person refuses as `unsupported_operation` (`BrowseStatus.LoginsUnreadable`) rather than browsing logged out; a record of the first, never-deployed format (version 1, bare domains) reads as nothing remembered. The record holds Playwright storage state (cookies, localStorage, IndexedDB — all three round-trip on Camoufox) and the remembered logins. **A login is a record, not a domain** (`SiteLogin`): its `Site` is the registrable domain of the url handed to `web_login`, and its `Domains` are every domain the handoff touched — the registrable domains of its main-frame hosts and of every cookie added or changed between the lease's snapshot and the settle, because an SSO iframe or a cross-domain API sets cookies on hosts the main frame never visits. The snapshot falls back to the record's cookies when the person has no context yet, since the context made next is restored from exactly that. A domain is `RegistrableDomain`, by the vendored public suffix list (`Domain/Tools/Web/public_suffix_list.dat`, ICANN and private sections, refreshed by hand), so people's sites on a shared host such as github.io stay apart. **Every save writes only what a remembered login covers** (`StorageStateFilter.Only`), so an unticked login's cookies, and a third party's, never reach the disk; a domain a remembered and a live-only login share — a provider both sign in through — is written because the remembered one needs it. Done ticked adds or replaces the site's remembered login (domains merged) and drops its live-only one; unticked removes a remembered login of that site, if any, and makes it live-only; neither touches another login, so an unticked login through Google leaves Google remembered for the logins that need it. A handoff that runs out is live-only unless its site is already remembered, and one that touched nothing is no login. **Live-only logins are held in memory only** (`PersonLogins`), beside the context that holds them, because they die with it — a written list would be stale after one restart — and all of them are forgotten when the browser's contexts close with their connection (`IPersonContexts.ContextsClosed`). **A full export happens only when a login is kept or forgotten**; the save after use — `Logins:SaveDebounceSeconds` after the person's first request since the last save, never pushed off by steady traffic, never while a lease is open — exports cookies alone (`IPersonContexts.ExportCookiesAsync`) and lays them over the stored origins, because it exists only so rotated cookies survive a restart and a mail client's IndexedDB runs to tens of megabytes. A record past `Logins:MaxRecordBytes` is written without IndexedDB, then without localStorage, never without its cookies, and says so in a warning. A login is used when a request goes to its own site, not to a provider it shares. No model tool reads or writes the store.

**A person sees and revokes their logins on a page; the model can only hand them it.** `web_logins` mints a link to `/browse/logins/<token>` under the handoff's rules — one claim, ten minutes, bound to the person when it is minted (`LoginsPages`), so nothing the page sends can name somebody else. The page lists `PersonLogins.LoginsAsync` by site — remembered or live-only, when it was handed off and last used, and the other domains it covers — with Forget by site. Forget removes that login and strips only the domains no remaining login (remembered or live-only) still covers, from the live context — rebuilt from its state without them (`IPersonContexts.ReplaceStateAsync`, closing their tabs, the only way to clear localStorage without a per-origin API, and skipped when nothing is stripped) — and from the record, so forgetting a shop leaves the Google session another login signs in with. It is refused while one of the person's leases is open. `PersonLogins.HasLoginAsync` answers whether a person holds a login whose site or domains cover a given site. No model tool lists or forgets: a page must not be able to talk the agent into revoking a session or covering its tracks.

**Password values never leave a snapshot.** The accessibility snapshot reports a filled password field as `AccessibilitySnapshotService.MaskedPassword` and an empty one as empty, in every context — whoever typed it.

## Overlays

`ModalDismisser` runs on every navigation and closes an overlay in three steps, each costing more
than the last and each run only when the one before came up empty: a button selector, a word in a
control's accessible name, and — for an overlay both left standing — a judgment (`ModalJudge`,
`Domain/Tools/Web`) over what its controls say, asked of Jev with `{ overlay_kind, controls }` and
nothing of the page. A cookie wall is asked *reject* then *accept* and a confident reject is taken
first, so it closes with the fewest cookies where the page offers it; `none`, a pick under the bar,
a stale click or a late answer leave the page exactly as before.

**A name is a label, and some controls are never offered.** An accessible name is the control's
whole `textContent`, so it is cut to `ModalJudge.MaxNameLength` before it leaves the page — past
that it stops being a button label and starts being the page's words — and its quotes are escaped,
because the criteria are prose the page contributes a substring of and a name that closes its own
quote can write an instruction beside it. A control whose name reads as acting on the person's own
data (delete, pay, buy, transfer, deactivate) is filtered out of the list the judge is shown, so it
can never be picked: the container selectors are substring matches, a `confirm-modal` reads as a
newsletter, and nothing on this path can undo a POST. A wall with no control left to offer is not
asked. The dismisser keeps the uncut names, so the re-read before the click still compares the
name the page actually carries. The pick is clicked by index into
the same locator its name was read from, and the overlay predicate, the name script and the anchor
guard are one JS constant each so the three steps cannot disagree about which buttons are the
wall's. The judge and its bar, deadline and cap are the server's own `TypeSafe` / `Judgment`
settings; an empty key is the feature off. **A turn addressed to the Lemonade chat host asks
nothing** — the Jev client's rule, not this server's (`.claude/rules/mcp-hosting.md`). `web_browse`
reads the turn off the call's `_meta` and it rides `BrowseRequest.Caller` through the
dismisser to `ModalJudge.PickAsync`; the client answers `AbsenceReason.LocalTurn`, which the judge
reads as `NotAsked` rather than a miss, so the wall is left to the model exactly as with no key.

**Every detected overlay is counted, and a wall that closed is not a miss.** `DismissAsync` answers
one `ModalOverlayOutcome` per overlay the last pass detected — `selector`, `text`, `judgment` or
`left-standing` — and the browser publishes each as a `ModalDismissalEvent` (dashboard: Web). The
container selectors overlap, so one wall matches several patterns; after any dismissal the page is
rescanned and a kind whose container is gone is dropped rather than counted as left standing, while
one still there is a separate wall and goes to the judge like any other. A judgment nobody asked
reports no latency, so a page with no key cannot drag the judgment average to zero. That is why this server holds a
Redis connection: it carries metrics and the login handoff's state (see Browsing as a person), and page images still cross at the agent's bridge.
`.scratch/jev-modal-dismissal/probe/README.md` is the probe the questions were measured on, kept as
`ModalJudgeJevTests`; change a question's wording only with that test green.

## Tabs

A browse session holds up to three live tabs, and a ref finds its own (`docs/adr/0034`). The tab protocol — everything that happens to a tab when a call touches it — lives in `BrowserSessionManager`, whose interface is four per-intent methods plus pool lifecycle: `BrowseAsync` (browse a URL; always supersedes the tab's refs), `OnRefAsync` (routed by ref; answers the routing walls), `OnCurrentTabAsync` (the ref-less default), `OnUrlAsync` (the composed-snapshot exception). A caller hands over the work to do on the page and receives the work's result or a named wall (`TabOutcome<T>`); the ordering, the locks, the stamp leases and the closed-vs-disconnected disambiguation never cross the seam, and the whole protocol is unit-tested in milliseconds against faked pages (`TabProtocolTests`). `PlaywrightWebBrowser` only carries pages around. Read the module top to bottom for the ordering — this file deliberately does not restate it.

**Tabs are invisible.** No tab handles, no tab list, nothing in any envelope or prompt — routing is carried entirely by refs. A `t-` namespace was considered and declined.

**Every ref is session-unique.** Each namespace (element `e-`, image `i-`) keeps its own monotonic counter in session state, handed to the stamping scripts as a starting number; a number is never reused within a session, which is what makes the silent wrong-picture answer unrepresentable. One shape rule — letter, dash, number — covers both namespaces (`ElementRef` / `ImageRef` in `Domain/Tools/Web`); the stamp spelling, the diff's strip regex and the not-found copy move together. A non-navigating `web_action`'s implicit capture **augments** rather than restamps — existing refs stay on the document and only newly appeared elements get fresh numbers — because a restamp there superseded the refs the model was mid-flow with and a four-field form died after its first fill (the eval web fixtures are the regression tests). An explicit `web_snapshot`, a browse and any navigation still restamp the whole document.

**A ref routes to the tab that stamped it.** `web_action` and `view_image` act wherever their ref lives; the session's registry of ref range → tab is what answers. The ref-less operations — `web_snapshot` and `back` — address the **current tab**: the tab the last call of any kind touched, `view_image` included, so peeking at an old tab's picture refocuses it. `back` walks its tab's own history. One exception: the snapshot composed with `web_browse` (`snapshot=true`) names the page the browse landed on (`SnapshotRequest.ForUrl`) and refuses if that tab is gone, because a parallel browse can move the current tab between the two calls — falling back would attach another page's refs to this page's text.

**`web_browse` reuses before it opens.** A URL matching a live tab exactly — by the address asked for *or* the address landed on, since redirects split the two — reloads that tab in place and restamps its refs with fresh numbers; anything else opens a new tab, evicting the least-recently-touched at the cap. Parallel browses of different URLs get different tabs and genuinely run in parallel.

**A popup is adopted as a tab.** `target=_blank` / `window.open` pages join the pool (popups of popups included), count against the cap, become current, and the action that spawned one answers from it — its URL, its content, its freshly stamped refs — instead of a stale diff of the page left behind. The browser reports a popup only once the new page says it is ready, which can land after the click has returned and settled, so a click that leaves its own page's URL and its target's surroundings unchanged waits up to `_popupGrace` (1.5s) for one; the wait ends the moment a popup is adopted against that tab, so only a click that really did nothing pays it.

**A stale ref refuses through one of two walls, each naming its recovery.** *Superseded* — the tab is open but a later snapshot or in-tab navigation renumbered it — says to snapshot or browse the page again. *Closed* — evicted at the cap — names the URL the ref belonged to (the most recent address the model asked that tab with; a popup adopted as `about:blank` and landed elsewhere names where it landed, since nobody asked for it). The registry keeps tombstones past eviction and dies with its session — an expired session keeps the existing dead-session refusal, never a third wall. Refs are not remapped onto a reloaded page.

**The registry is bounded, and overflow degrades quietly.** `BrowserSession.MaxRanges` is 128, dropped oldest-first. A ref whose range has aged out routes as *unknown* and falls through to the current tab's ordinary not-found — a third outcome, weaker than either wall, and the one place the registry stops answering "which tab stamped this". It cannot resolve to the wrong target (a number is never reused, so it matches nothing), but it does produce the vague refusal the two walls exist to replace. Raising the bound trades memory for how far back a ref can still name its page.

**One idle clock, one LRU rule.** The session-wide idle timeout is refreshed by every routed call, so an actively acting session cannot be pruned mid-use; tabs have no clock of their own and die individually only by eviction. The tab cap and the idle timeout are ordinary settings in the browse server's own `appsettings.json` (`Browsing:TabCap`, `Browsing:SessionIdleTimeoutMinutes`) — generic tunables, no compose entry. Locking and lock ordering are the module's own invariants now, held by code and its tests rather than by this file.

## Images

`web_browse` writes an entry into the markdown body where each image sits — its ref and the best label the page gives it — and `view_image` fetches by ref through the same page. See `docs/adr/0033`.

**Image refs are their own namespace.** `i-1`, `i-2`, never mixed into the `e-` refs the snapshot assigns. A tool handed the other kind refuses it by name rather than failing to find it. Both live in the browse session and die with it; a ref from a dead session says to browse the page again rather than erroring vaguely.

**Entries are positional, so they cost body budget.** They sit in the text that `maxLength` and `offset` paginate over, which means an image-heavy page shifts the text window. `HtmlConverter.Truncate` must never cut an entry in half — it backs up past a partial one the same way it backs up to a newline (which it does when the last newline falls past 70% of the target, and the target is `maxLength` minus the suffix, not `maxLength`) — and the envelope reports how many images lie beyond the window. A ref the model can see is always a ref it can use — an entry longer than the whole window goes out over budget rather than being backed up to nothing, because a window that consumes nothing is a page paging can never get past. Because the cut backs up (and the body carries a suffix), the body's length says nothing about where the next window starts: a truncated envelope carries `nextOffset`, the position the cut actually landed on, and paging by `maxLength` instead skips exactly what the back-up left — including entries `imagesBeyondWindow` just promised.

**The size filter needs rendered dimensions.** Under ~100px on either side an image is a spacer, an icon or a tracking pixel: no entry, no ref, unreachable. Markup `width`/`height` lie, so ask the page. `StripDomNoiseAsync` keeps `src` for images that pass — it strips it for everything else, as before.

**A fixture image must actually load, or the measurement is a race.** A test image pointing at an address that 404s renders at its declared CSS size only until the request fails; once it does, Firefox stops honouring the box and the element collapses to its alt text — under a hundred pixels, so the filter drops it as furniture and a restamp erases the ref. A single-pass test usually measures before the failure comes back and passes; a test that stamps twice is deciding on whether a 404 has returned yet, which is what made `SessionUniqueRefTests` fail only under full-suite load. Use a `data:` URI (decodes instantly, cannot fail) or Playwright's `RouteAsync` with real bytes, and await `onload` before measuring. The images in `PageImageMeasurementTests` are single-pass and carry this fragility latently — don't add a second pass to one without giving it a picture that loads.

**A renderer that flattens must still list its pictures.** `ConvertTableToMarkdown` writes each cell as flat `TextContent` so a row stays on one line, and an `<img>` contributes nothing to text — so every picture inside a table used to vanish, and commons.wikimedia.org's featured pictures (all 47 of them, gallery and picture-of-the-day alike) answered as a page with no images at all. Cells append their entries via `ListImagesWithin`, the same call the anchor case uses, after the cell's own words. Both of the table walk's selectors are also scoped to the table's own rows and the row's own cells (`Closest(...) == ...`): `QuerySelectorAll` is descendant-wide, and Wikimedia frames a table inside a cell, so an outer table re-rendered the inner one's rows and repeated a ref that names exactly one picture. Any future renderer that flattens a subtree owes the same two things — list what it flattened, and don't render a nested one twice.

**Labels fall back before going blank**: alt → figcaption → title → enclosing link text → filename → rendered dimensions. A list of entries all called "image" is not a menu.

**One picture, one label — by construction.** `ImageLabel.From` (`Infrastructure/HtmlProcessing`) is the only code that turns what a page offers into a label; the entry builder and `view_image`'s fetch both feed it a facts record, so the entry and the note that replaces a fetched picture speak the same words because there is nothing else that could speak. The fetch script computes no label — it answers facts (the raw strings and stamped dimensions), and the ladder used to exist a second time inside it, in JavaScript, where the two engines silently disagreed about Unicode whitespace and anchoring; those edges are named unit facts in `ImageLabelTests` now. Two things the code cannot say for itself: the 500-character cap is a safeguard, not an editor — 120 cut APOD's alt mid-sentence on every browse, and a real label should never meet the cap — and the cut backs off to a text-element boundary, so a label ending in an emoji never leaves as a lone surrogate half.

**`view_image`'s cap of 8 is spelled three times**: `ViewImageTool.MaxPerCall`, the tool description, and the MCP parameter description. The two prose copies are hand-synced with the constant.

**Bytes as served first, pixels only when no fetch can obtain them.** The descent — wire fetch, canvas read, context request, element screenshot, each step down trading fidelity for reach — is owned by `ImageAcquisition` (`Infrastructure/Clients/Browser`), one probe call per rung behind `IImagePageProbe` (Playwright-backed in production), every step decided in C# and unit-tested against a faked probe (`ImageAcquisitionTests`); read the module for the ordering — this file deliberately does not restate it. What the module cannot say for itself: the credentials rule is a trap that already broke one implementation — same-origin fetches carry the page's credentials, cross-origin goes **anonymous**, because the big image CDNs send ACAO `*` and a wildcard is precisely what a **credentialed** request is rejected against; don't "fix" cross-origin to send credentials. Only wire rasters (one constant in the module, media type trimmed once) leave as served — as-served `image/svg+xml`, Wikipedia's site logo, made the vision provider refuse the whole request with HTTP 400 — and a tainted canvas is not a refusal but two more rungs, because CORS binds script inside the page and nothing else (`docs/adr/0033`). SiteRefused remains only for an image the browser itself will not show, and a dead link answers its own NeverLoaded wall rather than inviting retries.

**`view_image` takes a list, capped at 8.** Over the cap, the first eight are fetched and the rest named in the envelope — partial success, so a greedy call progresses. The cap counts images, not bytes; eight full-size images can still fail as an oversized request, and that is accepted (`docs/adr/0033`).

**The bytes cross at the bridge, not here.** The MCP server returns a protocol image block and knows nothing of Redis, conversation ids or tool call ids. `QualifiedMcpTool` lifts the `DataContent` out into `IReadImageStore` and substitutes the envelope, so the history stays text-only and hydration treats a page image exactly like a `file_read` image — same 20-message distance, same forget-on-exit, same placeholder. Do not use this server's Redis connection to shortcut that — the one it holds carries metrics and the handoff's own state, never page images.

**One call can answer with several pictures, so a key carries an index.** `IReadImageStore` holds one image per key and `file_read` depends on that, so `view_image`'s pictures are keyed `<callId>#<n>` rather than widening the store. **`n` counts blank-line-separated paragraphs that start with `{`, not pictures and not content blocks** — the call's own envelope leads each result and takes index 0, and a refused image takes a slot with no bytes behind it. The unit is deliberately the paragraph: a `{`-paragraph embedded inside a foreign text block takes a slot on both sides, so "fixing" either side to count `AIContent` blocks instead would silently re-offset every key. `McpImageLift` and `ReadImageHydration` compute that number independently on either side of the wire, so they must ask the same question the same way; `PageImageRoundTripTests` drives both halves over a real `ToolResponse.Create` result and is what stops them drifting. They already had: counting pictures on one side and blocks on the other put every image one key off its bytes, and every one of them hydrated as "no longer in view".

**Every refusal names its wall**: no vision on the model, dead session ref, not-an-image ref, site refused the fetch, a dead-link image whose bytes never arrived (no retry invited — distinct from a CDN guarding pixels the page displays), past the per-call cap, bytes already forgotten, and the two stale-ref walls in the Tabs section. One generic "unavailable" leaves the model unable to tell a retryable failure from a permanent one. `ImageFetchStatus` carries `Success` plus exactly the five a fetch can reach — the three image walls (not-an-image, site-refused, dead-link) and the two stale-ref ones. The remaining four are answered off the fetch path: a dead session and the per-call cap before one is attempted, no-vision and forgotten-bytes agent-side afterwards. Don't add a status for those; a status nothing can produce is a refusal nobody can receive, and the enum says so where it is declared.

**The no-vision wall is answered agent-side, not here.** The capability catalogue and the turn's resolved model both live hub-side, so `McpViewImageTool` passes `modelAcceptsImages: true` unconditionally and hydration leaves the note instead. `ViewImageTool`'s own refusal is therefore unreachable through MCP and fires only for a direct domain-tool caller — it is kept because the tool is the thing being tested, not dead code to delete. The cost is that a vision-less turn still fetches and stores the bytes.

## Camoufox

The `camoufox` service is an anti-detect Firefox for scraping, reached at `ws://camoufox:9377/browser`; config in `McpServerWebSearch/Settings/McpSettings.cs` (`CamoufoxConfiguration`).

**Bumping `Microsoft.Playwright` is a two-sided change.** The connect handshake demands an exact client/server minor match — a mismatch fails hard with HTTP 428 `Playwright version mismatch`. `DockerCompose/camoufox/Dockerfile` must move in lockstep: both the `mcr.microsoft.com/playwright:vX.Y.0-noble` base and `playwright-core@X.Y.0`. Camoufox's bundled Firefox carries an older juggler protocol, so a newer playwright-core can send fields it rejects; `patch-viewport.js` strips the `screenSize`/`isMobile` fields 1.61 added (upstream [camoufox#653](https://github.com/daijro/camoufox/issues/653) — their own Python library just pins `playwright<1.61`). Both `patch-*.js` scripts are anchor-checked and **exit 1 when their anchor disappears**, so a bump fails the image build loudly instead of shipping a broken browser. Rebuild the image and run `Tests/Integration/Clients/` after any bump. `CamoufoxPlaywrightVersionTests` pins the two sides' minors to each other.

**The browser is pinned by the library version.** Each `@camoufox/camoufox` release is stamped with the browser build released beside it (`dist/data-files/browser-pin.json`), and `camoufox fetch` installs that build, so updating Camoufox is bumping the one npm version in the Dockerfile; `CamoufoxPlaywrightVersionTests` refuses the old `camoufox-js`, which took whatever release was newest at build time. The pairing also keeps the fingerprint properties the library writes in step with the ones the browser knows — `camoufox-js` against a 156 build died at launch with `UnknownProperty: navigator.product in config`. `npx camoufox active` in the image names the build. The pin can be a prerelease, and today is: 156.0.1-beta.34.

**One device for the life of the deployment.** Camoufox draws a fresh identity per launch unless handed one, and a site that sees a logged-in session arrive from a new machine after every deploy challenges or drops it. `fingerprint.js` draws an fpgen fingerprint on the first launch over an empty `camoufox-identity` volume, saves it to `/data/fingerprint.json`, and `server.js` hands it to every launch; every per-identity draw (fonts, voices, audio seed, WebGL) is seeded from it, so the file is the device. A file that will not parse keeps the container down rather than drawing a new one. `check-fingerprint.js` runs at image build against `fingerprint-fixture.json.gz`, one saved by the package the pin was introduced with: a bump that refuses it, or presents it differently from one launch to the next, fails the build. Anonymous and person contexts share the device — cookies, not fingerprints, separate them. `CamoufoxFingerprintPinTests` launches twice over one volume; it reuses the `camoufox:latest` image like every other fixture, so rebuild that image after touching this directory.

**uBlock Origin runs, and only builds from 156.0.1-beta.32 on can carry it.** Earlier Camoufox installed add-ons once per window, so each Playwright page reloaded uBlock's background page and a request could wait on a `webRequest` listener that had gone away ([camoufox#185](https://github.com/daijro/camoufox/issues/185)). The symptom is a stall of every request partway through a few parallel browses — a channel suspended in `WebRequest.sys.mjs` and never resumed, `data:` pages still rendering — until the browser restarts; in `Tests/Integration/Clients/` it shows as a run of 30s "Request timed out" browses. Moving the pin backwards past beta.32 means `exclude_addons: ['UBO']` in `server.js`. The add-on itself still floats (AMO's latest at image build), and it fetches its filter lists on every launch, so the first few seconds after a restart browse unfiltered.

**Our scripts run in an isolated world.** Since Camoufox 152.0.4-beta.29 every `EvaluateAsync` lands in an isolated world (a `mw:` prefix reaches the page's own, and only with `main_world_eval` on at launch). The DOM is shared, but page-made objects are seen through Xrays: indexing a `Uint8Array` throws, so `PlaywrightImageProbe`'s wire rung reads bytes with `FileReader`. A script that silently returns nothing after a browser bump is the first thing to check here.
