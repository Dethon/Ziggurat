# Satellite Hardware, Build & Deploy

The crate-wide invariants and the wire protocol are in `satellite/CLAUDE.md`. `scripts/provision-satellite-rs.sh`'s header and inline comments explain each knob and branch; this file keeps the commands and the device gotchas.

## Hardware: reSpeaker XVF3800 + MiniAmp (deployed fran-office unit)

- **Format**: 16 kHz-native S16LE both directions, 2ch (both channels carry the same signal, so `plughw` stereo→mono averaging is fine). Provisioning auto-detects the USB capture card by NAME (`arecord -l`) as `plughw:CARD=<name>,DEV=0`; capture needs no resampling, and `plughw` resamples only the 22 050 Hz playback to a rate the speaker lists (44100/48000 on the MiniAmp). ReSpeaker 2-Mic HAT override: `plughw:CARD=seeed2micvoicec,DEV=0` on both audio commands plus `--button-gpio 17`.
  - Don't redo: `snd_usb_audio index=0` pinning (collides with the Pi's vc4-hdmi + headphone cards in slots 0-2, USB probe fails -16, no card created); an `/etc/asound.conf` 48 kHz plug device (capture is 16 kHz-ONLY: "no configurations available").
- **Firmware is load-bearing and upgradable in place.** Read it: `sudo LD_LIBRARY_PATH=. ./xvf_host VERSION` from `/opt/xvf3800-host/` (or `lsusb -v -d 2886:001a | grep bcdDevice`); compare against `respeaker/reSpeaker_XVF3800_USB_4MIC_ARRAY` → `xmos_firmwares/usb` (plain files, no tags). Flash over the live USB link (runtime DFU, no re-cabling), with `nabu-satellite` and any feeder stopped: `sudo apt-get install -y dfu-util && sudo dfu-util -R -e -a 1 -D <fw>.bin`. Alt 1 is the upgrade partition, alt 0 the factory fallback (`xmos_firmwares/recover/4mb_all_ff.bin`). **Take the plain 2-channel build ONLY** — `_48k` and `6chl` break the 16 kHz/2ch contract.
- **Capture-clock quirk, fixed in 2.0.10.** Firmware ≤2.0.6 only clocks capture while its own playback runs — capture alone opens with EIO, and a live capture dies the instant playback stops — hence provisioning's `nabu-micclock.service` feeder (an endless zero-stream). The deployed unit runs **2.0.10** with no feeder; the 2.0.6→2.0.10 flash kept mixer levels, every `xvf_host -d` parameter and the capture format. The probe + feeder stay for other UAC hardware; the verdict is **sticky across re-provisions** (the probe is valid only on a COLD engine: once the feeder has run the engine stays clocked for minutes, so a warm re-probe would tear down a still-needed feeder), so retiring a feeder after a firmware upgrade or hardware swap means `sudo rm /etc/systemd/system/nabu-micclock.service` first.
- **Speaker output** is the HiFiBerry MiniAmp (`dtoverlay=hifiberry-dac`, card `sndrpihifiberry`) via PipeWire; WirePlumber rules exclude the reSpeaker card and disable HDMI/jack so the HAT is the only sink.
- **AEC: NEGATIVE result, don't redo without new hardware** (2026-07-16, re-checked at 2.0.10). With playback on the external MiniAmp the XVF3800's echo cancellation stays inert (linear ERLE 0.0 dB at every reference delay 20-120 ms, `AEC_AECCONVERGED=1`) even with a clean, level-balanced far-end reference; the firmware's echo model assumes the speaker on its OWN 3.5 mm out (`AUDIO_MGR_SYS_DELAY` trims only ±64..256 samples). Real AEC needs an analog amp on the XVF3800 jack, or new firmware.
  - Gotchas: the Array's UAC `PCM` mixer ships at −23/−20 dB as headroom for the ×8 `AUDIO_MGR_REF_GAIN` — 0 dB hard-clips the reference (stored at −13/−20 dB via alsactl). A filter-chain sink's monitor taps the POST-graph signal. DSP taps: `xvf_host` mux cat 4/12 far-end pre/post gain, cat 3 mic into SHF, cat 7 + `AEC_ASROUTONOFF 0` linear residual.

## Build & Deploy

`scripts/build-release.sh` cross-compiles via cargo-zigbuild + zig — **never run bare `cargo zigbuild` for releases** (fp16 CC shim and `.cargo/config.toml` target-cpu pinning: `satellite/README.md`).

`scripts/provision-satellite-rs.sh <user@host> [mic-device]` installs the binary and the templated `deploy/nabu-satellite.service` (only dependency `alsa-utils`; `performance` governor, `Nice=-10`) plus a USB-autosuspend-off udev rule.

- **The office unit's exact command is in `satellite/README.md` → "Deploying the office unit"**: `MUSIC_HUB=192.168.5.45 MUSIC_ROOM=fran_s_office scripts/provision-satellite-rs.sh dethon@192.168.5.11`. Never provision it without the `MUSIC_*` pair: it comes back voice-only. The same section has the binary-only path for when the drop-in directory must survive.
- **I2S DAC/amp HATs** (MiniAmp) declare `DAC_OVERLAY=hifiberry-dac` — I2S is undiscoverable, so the script writes the dtoverlay, reboots and continues.
- **Music units**: three per-source softvols (`Music`, `TTS` at `TTS_VOLUME`% default 100, `Alert` at `ALERT_VOLUME`% default 100) under a PipeWire master started at `MASTER_VOLUME`% (default 50); wireplumber persists later changes, so that is only where a (re)provision puts it. The MiniAmp has no hardware volume: every level is software. `TTS` carries replies and cues; `Alert` carries only hub-marked timer/alarm streams via `--alert-snd-command` (`.claude/rules/voice.md`, "Alert routing"). An alert rings through master × `Alert`, so a lowered master quiets alarms too. Tune live: `amixer -c <card> sset TTS <pct>%` / `sset Alert <pct>%` + `sudo alsactl store`. **A re-provision without explicit `TTS_VOLUME`/`MASTER_VOLUME` resets a calibrated unit to factory levels** — pass its calibrated values. Ducking and the volume backends: `.claude/rules/satellite-volume.md`.
- **Voice-only units**: one softvol master (`pcm.speaker` → `Nabu Volume` + `Nabu Switch`), asserted to `MASTER_VOLUME`% unmuted every run and materialized by playing 1 s of silence through it (a softvol control exists only after its first open), re-landed once per **boot** (a reboot wipes it, and its first open recreates it at MAX) by the `nabu-volume-init` oneshot (`After=alsa-restore`, `Before=nabu-satellite`), never per service start, so a crash-restart cannot stomp a level set by voice. Replies, cues and alerts all pass through it (the binary's `--alert-snd-command` defaults to `--snd-command`, `satellite/src/config.rs`). **The provisioning open of the chain is a gate**: if it fails, provisioning deletes `/etc/asound.conf`, reverts `--snd-command` to the raw device, installs no volume flags and removes the `nabu-volume-init` unit, because playback errors are connection-fatal under `Restart=always`. A card name it cannot derive takes the same no-flags path; a music → voice-only downgrade **rewrites** `/etc/asound.conf` rather than deleting it. The control name lives in ONE shell variable so asound.conf, `amixer` and `--volume-mixer` cannot drift.
- **Wake sensitivity**: `THRESHOLD` (default 0.5) and `WAKE_WINDOW` (default 3 — 80 ms scores **averaged**, not consecutive frames) apply to both unit paths. The defaults belong to the shipped classifier (`ok_nabu_custom_v13b`); a classifier swap is a re-tune. Retune one knob at a time and judge a window change on live false wakes, not only benchmarks (0.5 / 2 woke on speech blips in prod, 2026-11-03). `TRIGGER_LEVEL` / `--trigger-level` stay as aliases because `Config::parse` errors on unknown arguments and a stale unit would loop under `Restart=always`. **Above 3, raise `--wake-preroll-ms` (240 ms) in the same change** or speech onset is clipped. Substitutions rewrite the flag's argument, never match a literal default.
- **`WAKE_MIN_RMS` (default 350, 0 = off)** drops wakes out of a near-silent room (the classifier scores silence as high as a real wake). A dropped fire is not a turn (no cue, no LED) and logs one info line, `wake rejected: quieter than --wake-min-rms`, with score and rms. **350 is this unit's measured number**; it is per-microphone, the XVF3800's AGC holds speech far above its ~40-110 idle floor, and a mic without AGC needs its own measurement before the flag is set.
- **`WAKE_QUIET_RMS` (default 200, 0 = off)**: while the room's level is under it, `WAKE_QUIET_THRESHOLD` (0.9) / `WAKE_QUIET_WINDOW` (2) replace `THRESHOLD` / `WAKE_WINDOW`, catching one-frame false-fire blips loud enough to pass `WAKE_MIN_RMS`; for the first ~5 s of a connection nothing changes. **200 is this unit's number.** The level is the louder of two medians (last 30 s and last 15 s) on purpose: a median, not the minimum the hub is sent as the room floor (a minimum reads quiet straight through TV dialog), and two windows so it rises fast and falls slowly — either window alone lost a real wake in manual testing (2026-10-13). Don't tighten `THRESHOLD`/`WAKE_WINDOW` globally instead: that costs wakes under TV.
- **qemu smoke tests need `--no-wake`** (`satellite/README.md`). On-device E2E validation is still open — it should also read the `RUST_LOG=debug` per-chunk "wake inference" timing line.

## Running on WSL

`scripts/wsl-satellite.sh` (WSLg PulseAudio) and `scripts/wsl-satellite-winaudio.sh` (Windows-native ffmpeg/ffplay; WSLg's RDP audio bridge degrades playback). Their header comments carry the env knobs and latency caveats; `README.md` has the manual invocation.
