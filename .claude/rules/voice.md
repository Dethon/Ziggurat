# Voice Satellite Architecture

Voice is an MCP channel server (`McpChannelVoice`, channelId `voice`, container `mcp-channel-voice`, port 6015) plus hardware satellites. It registers with `AddChannelServer(DeliveryPolicy.Broadcast)`, so an idle-but-unpruned subscriber still receives and a brief agent gap does not cost a repeated utterance. `TranscriptDispatcher` emits through `ChannelNotificationEmitter` with `Location`, `SatelliteId` and `DismissedAlert` as named payload properties. The hub is the Wyoming **client**: `WyomingSatelliteHost` dials every satellite with an `Address` in `VoiceSettings.Satellites` (`Satellites__<id>__Address`) and reconnects forever; address-less satellites stay in the catalog as announce targets but are never dialed (announcements report offline).

Pipeline: satellite wake → `SilenceGate` → **speaker verification** (`Services/Verification`; non-enrolled audio dropped pre-STT) → optional **TSE** (`Services/Tse`) → **Lemonade STT** → `channel/message` → reply streamed through **Lemonade Kokoro**, resampled in-hub to 22 050 Hz.

**Who a turn acts for.** A speaker profile folder under `/voices` is named after its person's account user id (`scripts/enroll-voice.sh <user id>` refuses anything else); pre-account folders are renamed by `HouseholdMigration/Steps/VoiceProfiles.cs`, after which this hub and the TSE extractor must be restarted (profiles are read at start). `TranscriptDispatcher` asks `IAccountResolver` (channel `voice`, identity the folder name, this server's `Mcp:SharedSecret`, which accounts knows as `CALLERS__mcp-channel-voice`, at `Accounts:BaseUrl`) and stamps `Principal(voice, user id, Account)` with the display name as `Sender`; only a new conversation awaits the answer (up to `Accounts:RequestTimeout` when the service never answers). A new conversation's topic is the speaker's — a recognised speaker's account's and private, the guest's the household's and shared — and a conversation keeps the owner its first speaker gave it: a guest speaking into a person's conversation is in their private topic, a person speaking into a guest's is in a shared one. TSE's target speaker is the folder name, so the user id too. Everything else — a doubtful match, a folder no account holds, an accounts outage (logged) — is the **voice guest**, `Principal(voice, "household")` with no account and the satellite's `Identity` as `Sender`; an outage never becomes somebody, and the guest's user id is the fixed `household`, never the satellite's `Identity` (an operator may name it after a person). Only the guest's missing account keeps it from a person's memory, logins and Sugary log.

**The turn carries the accounts service's assertion** (`ChannelMessageNotification.Assertion`), which is what the agent believes (`.claude/rules/person-assertions.md`, "Channels and the agent"): a recognised speaker's comes with the resolution; the guest's is asked of `POST /accounts/internal/guest` (`IAccountResolver.GuestAsync`, the household's guest signed for `voice`) on every guest utterance. The agent signs the guest's calls as the guest *with its household* — never as nobody. No assertion at all (logged): an existing conversation's turn is still emitted and the agent refuses it (`AssertionRefused`, `Missing`); a new conversation's is refused at the topic mint (an `SttError` voice event, nothing emitted).

**Voice keeps no topics; the agent mints them.** No topic store and no Redis for topics here (its Redis is the metrics feed's alone). `VoiceConversationManager` asks `ITopicMinter` — `AgentTopicsClient` (`Agent:BaseUrl`, or the tunnel) — to `POST /internal/topics` (`TopicMinting.Path`, `Agent/App/TopicMintingApi.cs`) with `TopicMintRequest(AgentId, TopicName, Sender)` and the speaker's assertion in `X-Ziggurat-Assertion`, answered `TopicMinted(TopicId, ConversationId)`. The agent verifies it like a voice turn (`VerifyTurnAsync(…, voice)`) and mints for whoever it names; the body never says whose the topic is, and a missing, forged, foreign-channel or nobody assertion is 401 (`AssertionRefused`). A household's voice server asks through its tunnel's `topics` back-call, which names the tunnel's household (`BackCallProtocol.HouseholdHeader`, set over whatever the server sent): another household's assertion is 403 (`WrongHousehold`), so a server holding it cannot mint into that household. No secret guards the route: it is under `/internal`, which no Caddy route reaches (conformance-checked), and it rests on the signature. A failed mint fails the utterance before anything is emitted. A fire only voice delivers is minted by the agent before it calls voice (`DeliveryTargetResolver`, `.claude/rules/channels.md`), so voice's `create_conversation` only attaches: it declares `address` and `existingConversationId` alone and refuses a call with no conversation to attach to.

**Choosing the STT model.** `STT_MODEL` names it on both sides — the container pre-pulls it, the hub requests it (`Stt__OpenAi__Model`) — and the two must agree or the warmed model is not the one decoded with. A **fine-tune is a `user.` model** that needs `STT_MODEL_CHECKPOINT` (`org/repo:file.bin`, HuggingFace/ModelScope only — no local-path form; `DockerCompose/lemonade/entrypoint.sh`, which fails at boot without one). A fine-tune moves the confidence distribution: re-measure `AvgLogProbThreshold` / `ShortSpeechAvgLogProbThreshold` / `NoSpeechProbThreshold` on it.

**Alert routing.** Insistent announces (timers and alarms: the `/api/voice/announce` requests carrying `insistent`) are marked `alert: true` on the Wyoming `audio-start` (protocol 1.5, `SatelliteConnection.BuildAudioStart`); `InsistentAnnouncementController` is the only producer, via `PlaybackKind.Alarm`, and the playback queue derives the mark from that kind — no producer sets it. The satellite plays a marked stream on `--alert-snd-command` instead of `--snd-command`, so an alert is not capped by the conversational `TTS` level; an unopenable alert device falls back to the normal sink. `AnnouncePriority.High` is deliberately not the marker — approval prompts share it. Every other kind is unmarked, so a pre-1.5 satellite is unaffected. The satellite's level chain (`Music`/`TTS`/`Alert` softvols, PipeWire or ALSA master, `MASTER_VOLUME` / `TTS_VOLUME` / `ALERT_VOLUME` in `scripts/provision-satellite-rs.sh`) is `.claude/rules/satellite-volume.md`, "Local speaker volume", and `.claude/rules/satellite-hardware-deploy.md`, "Build & Deploy".

**A local mute must never swallow a timer or an alarm.** `InsistentAnnouncementController` re-sends `alert-hold` to every online target at the top of EVERY round (the satellite's hold dies with its TCP connection), and its `finally` discards its own `ActiveAlertRegistry` handle before `CountFor`, sending `alert-release` only where the count reached zero — overlapping alerts on one satellite are normal.

**A spoken approval is read for what it means, and never against the person.** `RequestApprovalTool` asks an `IApprovalReader`; `JudgedApprovalReader` puts prompt and transcript to Jev and acts by `Approval:Judgment`. **One asymmetry, deliberate:** a sure yes over a word list that heard a refusal re-asks; a sure no over a word-list yes still declines (refusing is the safe direction). The word list is the whole answer when the judge is off, absent, late or misconfigured; the caller's own cancellation propagates rather than falling back. **A turn addressed to the Lemonade chat host is read by the word list alone** — the Jev client's rule (`.claude/rules/mcp-hosting.md`), not the reader's. `RequestApprovalTool.McpRun` reads the turn off the call's `_meta`, present only because `McpChannelConnection.AskApprovalAsync` stamps it on the approval hop (`McpChannelConnectionApprovalMetaTests`).

**A spoken approval is its asker's.** For an account's question (`Principal.Of(turn)?.Account`), the answer's capture goes to `ISpeakerVerifier` first: a voice conclusively another enrolled person's, or rejected as nobody's, gets the `No entendí.` re-ask and is never taken as theirs, and two of them end it refused; `Skipped` (a one-word "sí") or `Unavailable` counts as the asker's. The voice guest's question is whoever answers aloud. Voice offers no `offer_approval`; the agent offers a voice-asked question on the person's other channels (`.claude/rules/channels.md`), and a prompt still waiting when they answer there is **called off** — the token ends the spoken prompt and closes the microphone, nothing more said. A question no satellite could put (none there, one gone mid-prompt, arbitration took the answer) answers `no_answer`, not `rejected`, leaving it to the offers; silence or two unclear answers is a refusal that ends it everywhere.

**The wording is measured, and the prompt is part of the wording.** `jev-approval-cases.json` labels answers against every prompt shape the tool speaks (natural-language, bare tool-name `¿Apruebas turn_off?`, several names, the `No entendí.` re-ask). Change a question's wording or the spoken prompt only with `ApprovalReaderJevTests` (`Tests/Eval/ModelChecks/`, armed eval) green, and re-probe rather than assume a number carries across shapes.

**The exec screen's reason is spoken before the question, never inside it.** A request carrying `ToolApprovalRequest.Screen` gets one short Spanish sentence (the first code's) ahead of the unchanged `¿Apruebas …? Di sí o no.`, first attempt only; the re-ask repeats the question, not the reason. The reader is handed the question alone — a reason folded in would be an unmeasured prompt.

**Local speaker commands.** `VoiceCommandMatcher` matches the normalized whole transcript against `VoiceSettings.Commands.Phrases`; `LocalCommandDispatcher` (`Services/LocalCommands/`) routes to the owning `ILocalCommandHandler`. `SpeakerVolumeCommandHandler` writes the satellite's `speaker-volume` event through `SatelliteSession.ControlWriter`. `TranscriptDispatcher` calls it after the gibberish gate and before `GetOrCreateAsync`, so poor audio cannot move a volume knob. A new local command is a new enum value plus a handler registration — `TranscriptDispatcher` stays untouched. Every phrase carries an explicit local marker: "sube el volumen" is a Music Assistant request and belongs to the agent.

**Short-phrase decode.** Every transcription POSTs a `prompt` from `WhisperPromptBuilder` (`Stt.OpenAi.Prompt`, per-satellite overridable), which replaces whisper-server's own `--prompt` — the container default serves only non-hub callers. Short commands stay whole because `Stt.Streaming` never splits before `FirstSplitAfterMs` (4 s; don't lower it — split commands decoded as wrong verbs), and `ChainContext` serializes decodes, so `MaxInFlightDecodes > 1` is inert (`SttSettings`). A short turn also gets the looser `ShortSpeechAvgLogProbThreshold` (`TranscriptDispatcher`).

**Decode ahead of the endpoint.** A turn capture whose speech pauses for `Stt.SpeculateAfterMs` (400 ms, under the 1.2 s tail by a decode; 0 is off) is decoded from that moment by `SpeculativeTranscription`, while the gate still waits out its trailing silence. The turn takes that decode only when it ended on the **same pause** (`UtteranceCapture.Pause`, compared by identity — any speech since throws it away) and TSE would have skipped it (`TseSpeechToText.Skips`; the decode is the raw chain under TSE, because it runs before the speaker check). Speaker verification stays on the full capture at close, so its thresholds see the audio they were cut on. Nothing a speculative decode does is visible until a turn takes it: the TSE skip is reported then, once, and the decode reports only `SpeculativeSttMs` (`used`/`discarded`/`failed`); `SttLatencyMs` is what the turn still waited, so the turn's spans keep tiling. One decode in flight per satellite — whisper decodes one request at a time.

**End-of-utterance floor.** The capture's noise floor is capped, never raised, by the satellite's `room_rms` on `run-pipeline` (protocol 1.7) and by `RoomNoiseMemory`; an inflated floor endpoints the user mid-sentence.

**One connection module, one host.** `SatelliteConnection` owns one run of the link; `WyomingSatelliteHost` dials, reconnects and owns the turn helpers (`CreateConnection` lets a test drive frames without a socket). **The unwind is split on purpose**: a synchronous phase releases the arbiter registration before the asynchronous drain, or a dead link can still win a wake and suppress a real command.

**One gate factory, one microphone, one turn module, one playback queue.** `SilenceGateFactory` alone assembles a satellite's gate — no gate-purpose parameter, so wake and approval captures get the same gate — and never assemble an `AdaptiveLevelTracker` at a call site. `Microphone.Close` pays back into `RoomNoiseMemory` as one act with closing. `VoiceTurn` owns the reply handshake with no settle route from outside; the reply tool ends a turn with one `EndStream()`. `CaptureSession` adds turn semantics over `Microphone`; its indicator events go through `SatelliteSession.TrySendControlAsync` and must never cost the user the utterance. `RequestApprovalTool` holds the `Microphone`, not a turn, so an approval never marks a turn start or speech end (`docs/adr/0013-the-microphone-and-the-turn-are-separate-types.md`). `PlaybackQueue` promises **exactly one outcome per job** via its `PlaybackTicket`, including refused jobs and jobs waiting when the link drops, and owns and disposes synthesis — no producer disposes anything (`docs/adr/0003-playback-settles-by-outcome.md`). The loop awaits only the connection's hooks (`PlaybackSink`); a producer's reaction to an outcome runs off the ticket and carries its own `try`/`catch`.

**Wire turn-taking.** Sending a `transcript` event ends the satellite's turn and re-arms wake; `FollowUpConversation` reopens the mic wake-free with the `ListeningChime` and a `listening-started` event (protocol 1.6) that returns the LED from Thinking to Listening — the satellite cannot infer the moment because its capture never closed. `WakeArbiter` picks one winner among satellites hearing the same wake (by the satellite's calibrated `wake_rms`) and silently re-arms the losers via `pause-satellite`; a much louder wake during another satellite's open conversation takes the conversation over, deliberately (`WakeArbitrationRules.CanSteal`).

**The satellite side is `satellite/CLAUDE.md` — read it before touching either side of the wire.** The satellite is the Wyoming **server**, and its playback sink is FIXED 22 050 Hz mono S16LE regardless of announced rates, so all hub-emitted audio (TTS, `ListeningChime`) must be 22 050 Hz. The image ships **no satellite and no locality**: a household's satellites live in the kit's gitignored `TenantKit/satellites.env` (`Satellites__<id>__*`) and its town in `.env`'s `VOICE_LOCALITY` (`TenantKitConformanceTests.TheKitsSatellites_AreTheSitesOwn_NeverTheVoiceImagesDefault`) — never a catalogue in `appsettings.json`, which every household's voice would dial on its own LAN. A dev run (`ASPNETCORE_ENVIRONMENT=Development`) dials the satellites `McpChannelVoice/appsettings.Development.json` names.
